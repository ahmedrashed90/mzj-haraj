MZJ Haraj Manager v1.16.0 CLEAN

CORE PUBLISHING MODEL
- One actual Haraj account and one company daily limit.
- The account daily limit is the only source of ad quantity.
- Publishing periods were removed from runtime, UI, validation, scheduling and exports.
- All eligible active reps share one continuous global round-robin queue.
- Eligible assignment rep = active rep linked to an active branch.
- Queue continues across days and resumes after the last rep found in existing assignments.
- Example with 14 reps and 4 ads/day: 1-4, 5-8, 9-12, 13-14-1-2, 3-6, 7-10.
- Rep branch follows the assigned rep automatically.

CONTACT ROTATION
- Every generated ad contains ALL active reps as contact snapshots.
- Each contact snapshot contains agentId, name and phone.
- Contact order rotates by one position for every next ad.
- Missing name or phone for any active rep blocks schedule creation.

AUTOMATIC WINDOW
- Automatic schedule starts on the same calendar day the button is pressed.
- Automatic schedule ends on the coming Friday, inclusive.
- Pressing on Friday creates a Friday-only window.
- Automatic quantity = dailyLimit * days minus already scheduled open ads in those days.

VEHICLE COVERAGE
- No vehicle repeats inside the same coverage cycle.
- After all eligible vehicles are covered, a new cycle starts automatically.
- Cars without complete CompareKey are excluded.
- Agency-location stock remains excluded.

WORD EXPORT
- PDF export is removed.
- Each branch exports a real DOCX file generated in-browser.
- DOCX does not include publishing-period or publishing-time columns.
- DOCX includes day tables, assigned rep/type/vehicle/link status, and publishing policies.

FIRESTORE
- settings/haraj_publishing
- haraj_accounts
- agents
- haraj_ads
- legacy publishing_periods collection is no longer read or used by v1.16.0.

WORDPRESS BRIDGE
- MZJ Haraj Ad Data Bridge v1.1.0
- Read-only endpoint /wp-json/mzj-haraj/v1/cars

- Word export: one weekly DOCX for all ads across all branches, grouped by day.
