# MZJ Haraj Manager v1.3.0 — Vercel + GitHub + Firebase Spark

نظام مستقل لإدارة تخطيط ومراجعة إعلانات حراج، بدون Firebase Functions وبدون Firebase Hosting.

## المعمارية

- **GitHub Private Repository**: حفظ السورس والإصدارات.
- **Vercel**: استضافة واجهة Vite وتشغيل `/api/stock` لقراءة الاستوك.
- **Firebase Authentication**: دخول المدير فقط `admin@mzj.com`.
- **Cloud Firestore**: حسابات حراج، المناديب، خطط النشر الأسبوعية، روابط الإعلانات وحالاتها.
- **MZJ Platform**: مصدر الاستوك فقط — قراءة فقط — لا يتم تعديل أي سجل داخل المنصة.

لا يوجد:
- Firebase Functions
- Firebase Hosting
- Firebase Storage مطلوب
- مستخدمون للمناديب
- بيانات وهمية

## أهم منطق v1.3.0

### 1) جدول نشر أسبوعي

من صفحة **مخزون السيارات**:

1. تختار السيارات المطلوب نشرها خلال الأسبوع.
2. تضغط **إنشاء تكليف أسبوعي**.
3. تختار أسبوع النشر.
4. النظام يوزع السيارات تلقائيًا على:
   - أيام الأسبوع من الأحد إلى السبت.
   - حسابات حراج حسب الحد الحالي لكل حساب.
   - جميع المناديب النشطين بالتساوي قدر الإمكان.
5. بعد الاعتماد تنتقل مباشرة إلى صفحة **جدول النشر**.

### 2) لا يوجد ربط مندوب بفرع أو حساب

المناديب عبارة عن قائمة شركة واحدة:
- الاسم
- رقم الجوال
- نشط / موقوف

لا توجد حصة يدوية للمندوب.

### 3) حدود حسابات حراج مرنة

يمكن تعديل حد أي حساب حراج إلى أي رقم `>= 0` في أي وقت.

إذا أصبح الحد الجديد أقل من عدد التكليفات الموجودة بالفعل في الأسبوع:
- يتم حفظ الحد عادي.
- يظهر تنبيه فقط.
- لا يتم حذف أو إلغاء أي تكليف سابق.

### 4) دورة تغطية الاستوك

الهوية الإعلانية للسيارة داخل النظام هي:

`سيارة + البيان + الموديل`

قاعدة التغطية:

**لا يتم تكرار سيارة/فئة في دورة النشر الحالية قبل أن تتم تغطية كل السيارات/الفئات الموجودة في الاستوك المتاح للبيع.**

مثال:
- الاستوك 40 سيارة/فئة.
- سعة الأسبوع 26 إعلان.
- الأسبوع الأول يمكن تكليف 26.
- الأسبوع الثاني تظهر الـ14 المتبقية أولًا.
- بعد تغطية الـ40 كلها تبدأ دورة تغطية جديدة تلقائيًا، ويمكن إعادة استخدام السيارات من البداية.

إذا دخل ستوك جديد أثناء الدورة، يظهر تلقائيًا ضمن السيارات المتاحة للتكليف.

### 5) صفحة جدول النشر

تعرض كل يوم:
- السيارة
- البيان
- الموديل
- المندوب
- حساب حراج
- الحالة
- رابط الإعلان

إذا عدى يوم النشر بدون رابط أو حالة نشر يظهر التكليف **متأخر**.

### 6) صفحة توزيع الأسبوع

تعرض:
- توزيع عدد التكليفات على المناديب.
- ما تم نشره والمتبقي لكل مندوب.
- قائمة السيارات المطلوبة من كل مندوب باليوم وحساب حراج.
- توزيع حسابات حراج.

`admin@mzj.com`

## قراءة الاستوك

Vercel API Route:

`GET /api/stock`

يقوم بالآتي فقط:

1. يتحقق من Firebase ID Token للمدير.
2. يسجل دخول Server-to-Server إلى منصة MZJ.
3. يرسل **GET فقط** إلى:

`/api/operations?resource=vehicles&status=available_for_sale&page=...&pageSize=200`

4. يستخدم فقط:
   - `car_name` = سيارة
   - `statement` = البيان
   - `model_year` = موديل
   - `status_name` / `status_code` = الحالة
5. يعرض فقط **متاح للبيع**.
6. يجمع الاستوك حسب `سيارة + البيان + الموديل`.

`api/stock.ts` لا يرسل أي PUT/PATCH/DELETE على المنصة، ولا يعدل حالة أو حجز أو بيانات سيارة. الـPOST الوحيد المستخدم هو تسجيل الدخول للحصول على Session لعملية القراءة.

## متغيرات Vercel المطلوبة

في:

**Vercel → Project → Settings → Environment Variables**

أضف:

```env
MZJ_PLATFORM_BASE_URL=https://mzj-platform.vercel.app
MZJ_PLATFORM_IDENTIFIER=بيانات_دخول_مستخدم_المنصة
MZJ_PLATFORM_PASSWORD=كلمة_مرور_مستخدم_المنصة
```

لا تضع كلمة مرور المنصة داخل GitHub.

## GitHub + Vercel

ارفع محتويات هذا الفولدر إلى Repository **Private** ثم اربطه بـ Vercel.

Vercel يتعرف على Vite تلقائيًا:

```text
Build Command: npm run build
Output Directory: dist
```

بعد كل Push إلى `main` سيعمل Vercel Deploy تلقائيًا.
