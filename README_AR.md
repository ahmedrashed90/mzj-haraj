# MZJ Haraj Manager — v1.11.0 CLEAN

نسخة كاملة CLEAN مبنية مباشرة على v1.10.0، مع إعادة تصميم صفحات جدول النشر والإعلانات وإصلاح تصدير PDF بدون Patch على Patch.

## الجديد في v1.11.0

### واجهة جدول النشر

- إعادة بناء صفحة **جدول النشر** بالكامل بتصميم احترافي مضغوط.
- كل يوم نشر أصبح مجموعة مستقلة Accordion.
- الضغط على اليوم يفتح كل إعلاناته معًا، والضغط مرة أخرى يغلقها.
- تم حذف عرض اللون الداخلي والخارجي من الجدول.
- الصف يعرض فقط البيانات التشغيلية المهمة: الوقت، الفترة، السيارة، الاسم/الفرع، النوع، عنوان الإعلان، الحالة، رابط حراج، وإجراءات النسخ.
- توجد معاينة اختيارية لنص الإعلان داخل صف الإعلان نفسه، وليس معاينة PDF.
- أزرار PDF أصبحت شريطًا مختصرًا لكل فرع بدل بطاقات كبيرة.

### واجهة الإعلانات

- صفحة **الإعلانات** تستخدم نفس نظام الأيام القابلة للفتح والإغلاق.
- الإعلانات مجمعة حسب يوم النشر بدل جدول طويل واحد.
- الفلاتر محفوظة، مع ملخص علوي للحالات والروابط.
- النسخ، الحالة، الرابط، الملاحظات والحذف كلها متاحة داخل صف الإعلان.

### PDF

- لا توجد معاينة PDF مرئية داخل النظام.
- التصدير يفتح نافذة الطباعة/الحفظ مباشرة.
- تم إصلاح تحميل CSS والصور داخل نافذة الطباعة باستخدام روابط مطلقة.
- تم إصلاح نسب أعمدة جدول PDF لمنع تكسير النص رأسيًا.
- تم رفع سعة صفحة اليوم إلى 18 إعلانًا حتى تبقى إعلانات اليوم معًا عند الحدود اليومية المعتادة.
- السياسات والمتابعة ما زالت في آخر صفحة فقط.

## وظائف v1.10.0 المستمرة

### 1) فترات النشر

من شاشة **إعداد النشر والمناديب** يمكن إنشاء أي عدد من فترات النشر. كل فترة تحتوي على:

- اسم الفترة.
- وقت البداية.
- وقت النهاية.
- عدد الإعلانات يوميًا داخل الفترة.
- المناديب المشاركون في الفترة.
- ترتيب المناديب داخل الفترة.
- تفعيل / إيقاف الفترة.
- تعديل / حذف الفترة.

مجموع عدد الإعلانات في الفترات النشطة يجب أن يساوي **الحد اليومي لحساب حراج** قبل إنشاء أي جدول جديد.

مثال: حد الحساب = 10 إعلانات يوميًا:

- صباحي 09:00–12:00 = 4 إعلانات.
- ظهري 13:00–16:00 = 3 إعلانات.
- مسائي 17:00–21:00 = 3 إعلانات.

النظام يلتزم بترتيب الأسماء داخل كل فترة حرفيًا. إذا كانت الفترة تحتاج إعلانات أكثر من عدد المناديب، يبدأ الترتيب من أول اسم مرة أخرى.

### 2) نوع المندوب: كاش / تقسيط

كل مندوب لديه حقل `agentType`:

- `cash` = كاش.
- `installment` = تقسيط.

يمكن تحديد النوع عند إضافة المندوب أو تعديله لاحقًا من جدول المناديب.

### 3) عنوان إعلان حراج حسب نوع المندوب

كل تكليف يحفظ **عنوان حراج مستقلًا** عن نص الوصف، ويظهر زر **نسخ العنوان**.

- مندوب الكاش: عنوان السيارة الطبيعي.
- مندوب التقسيط: عنوان تمويلي تلقائي، مثال:

`هيونداي اكسنت 2026 | أقوى عروض التمويل | بدون دفعة | أطول فترة سداد | أقل قسط شهري بالتأمين الشامل`

عنوان التمويل لا يُضاف داخل وصف الإعلان؛ هو مخصص لخانة **العنوان** في حراج فقط.

## صيغة وصف الإعلان

الوصف يظل مستقلًا عن عنوان حراج ويستخدم الصيغة المعتمدة:

- اسم السيارة.
- `متوفرة الآن`.
- الموديل والفئة.
- المواصفات الرئيسية.
- المواصفات الداخلية والخارجية والأمان من CompareKey فقط.
- الاسم ورقم الجوال.
- في النهاية: `السعر شامل الضريبة: ... ريال`.
- ثم: `احصل على الخصم والهدايا عند التواصل`.

لا تظهر كلمة `المندوب:` داخل وصف الإعلان.

## الجدولة

- يوجد حساب حراج واحد فعلي للشركة وحد يومي واحد.
- التوزيع لم يعد يعتمد على حصة تلقائية للفروع.
- التوزيع يعتمد على **فترات النشر** والمناديب المختارين وترتيبهم داخل كل فترة.
- فرع التكليف يُؤخذ تلقائيًا من فرع المندوب المختار.
- المندوب الموقوف أو الموجود داخل فرع موقوف لا يدخل تكليفًا جديدًا.
- كل تكليف يحفظ Snapshot من: الفترة، الوقت، ترتيب التكليف داخل الفترة، اسم المندوب، الجوال، النوع، الفرع، عنوان حراج، ونص الإعلان.
- إذا كان الحد اليومي 10 والفترة 5 أيام والسعة كلها متاحة، الناتج 50 تكليفًا: 10/10/10/10/10.

## منع التكرار ودورات التغطية

- السيارة لا تتكرر داخل نفس دورة التغطية.
- بعد تغطية كل السيارات المؤهلة يبدأ النظام دورة جديدة تلقائيًا حتى يملأ فترات النشر والحد اليومي.
- مثال: 21 سيارة مؤهلة + حد 10 يوميًا لمدة 5 أيام = 50 تكليفًا؛ 21 في الدورة الأولى، 21 في الثانية، 8 في الثالثة.

## CompareKey

`CompareKey` هو المصدر الوحيد للمجموعات الثلاث:

- المواصفات الداخلية.
- المواصفات الخارجية.
- مواصفات الأمان.

أي سيارة بدون CompareKey كامل ومربوط بالمجموعات الثلاث لا تدخل الاختيار أو الجدول التلقائي أصلًا.

## حساب حراج والفروع

- اسم حساب حراج الفعلي والحد اليومي: `settings/haraj_publishing`.
- الفروع محفوظة في `haraj_accounts`.
- كل فرع يملك `advertiserName` قابلًا للتعديل.
- القيم الافتراضية:
  - الملتقى → `شركة الملتقى للسيارات`
  - الصالة → `معرض محمد ذعار العجمي للسيارات`
  - القادسية → `معرض محمد العجمى للسيارات`

## Firestore

- `haraj_accounts`: الفروع الداخلية + `advertiserName`.
- `agents`: المناديب + الفرع + الحالة + `agentType`.
- `publishing_periods`: فترات النشر + الأوقات + العدد اليومي + قائمة `agentIds` المرتبة.
- `haraj_ads`: التكليفات وكل Snapshots وقت إنشاء الجدول.
- `settings/haraj_publishing`: حساب حراج الفعلي + الحد اليومي.

## مصادر البيانات

### الاستوك — MZJ Platform

قراءة Server-to-Server فقط:

`GET /api/operations?resource=vehicles&status=available_for_sale...`

```env
MZJ_PLATFORM_BASE_URL=https://mzj-platform.vercel.app
MZJ_PLATFORM_IDENTIFIER=
MZJ_PLATFORM_PASSWORD=
```

### مواصفات الموقع — WordPress

البلجن المرفق:

`wordpress-bridge/MZJ-Haraj-Ad-Data-Bridge-v1.1.0.zip`

Endpoint:

`/wp-json/mzj-haraj/v1/cars`

```env
MZJ_WORDPRESS_BASE_URL=https://mzjcars.com
MZJ_HARAJ_BRIDGE_KEY=<SECRET>
```

## PDF

- PDF مستقل لكل فرع.
- يعرض فترة النشر والوقت والاسم ونوع المندوب لكل تكليف.
- كل إعلانات اليوم مع بعض.
- إذا احتاج اليوم أكثر من صفحة، يكمل نفس اليوم أولًا.
- السياسات والمتابعة في آخر صفحة فقط.
- لا صفحات فارغة إضافية.
