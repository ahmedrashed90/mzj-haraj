# MZJ Haraj Manager — v1.7.0 CLEAN

نسخة CLEAN كاملة مبنية من v1.6.4، وليست Patch على Patch.

## منطق التشغيل الحالي

- **حساب حراج واحد فقط** هو مصدر سعة النشر للشركة كلها.
- اسم حساب حراج والحد اليومي يحفظان في `settings/haraj_publishing`.
- الحد اليومي يتوزع على **كل المناديب النشطين في جميع الفروع**.
- الفرع يستخدم للتنظيم والتقارير وPDF مدير الفرع فقط، ولا يملك حصة نشر مستقلة.
- المندوب في حالة إجازة / موقوف لا يدخل أي جدول جديد.
- السيارات لا تتكرر داخل دورة التغطية. إذا كانت السعة أكبر من السيارات الجديدة، تترك السعة الزائدة بدل تكرار نفس السيارة.
- سيارات `المكان = الوكالة` مستبعدة من نظام حراج.

## صيغة الإعلان التلقائية

عند إنشاء الجدول، النظام يطابق كل سيارة مع سيارة الموقع ويسحب بياناتها من WordPress / MZJ Cars Panorama / CompareKey عبر بلجن قراءة مستقل مرفق.

الصيغة تحتوي - حسب البيانات الحقيقية المتاحة - على:

- اسم السيارة والفئة والموديل.
- جملة `متوفرة الآن لدى <اسم حساب حراج>.` واسم الحساب ديناميكي من إعداد النشر.
- السعر الحقيقي من الموقع إذا كان موجودًا.
- المحرك، ناقل الحركة، عدد السرعات، الدفع، الوقود، الاستهلاك، الحصان، العزم، السلندرات، المقاعد، الضمان.
- أبرز المواصفات الداخلية والخارجية والأمان.

لا يخمن النظام أي مواصفة غير موجودة. إذا لم يجد مطابقة مؤكدة، يوقف زر النسخ واعتماد الجدول حتى لا يتم نشر مواصفات غير مؤكدة.

كل تكليف يحفظ Snapshot للنص الذي تم تسليمه للمندوب، ثم يظهر زر **نسخ صيغة الإعلان** في جدول النشر وصفحة الإعلانات. بعد النشر يسجل المندوب/الإدارة رابط حراج.

## مصادر البيانات

### 1) الاستوك — MZJ Platform

`api/stock.ts` يسجل دخول Server-to-Server ويقرأ فقط:

`GET /api/operations?resource=vehicles&status=available_for_sale...`

Environment Variables في Vercel:

```env
MZJ_PLATFORM_BASE_URL=https://mzj-platform.vercel.app
MZJ_PLATFORM_IDENTIFIER=
MZJ_PLATFORM_PASSWORD=
```

### 2) مواصفات الموقع — WordPress

يوجد داخل المشروع:

`wordpress-bridge/MZJ-Haraj-Ad-Data-Bridge-v1.0.0.zip`

ثبته كبلجن جديد مستقل على WordPress. لا يعدل Panorama ولا السيارات، ويقدم قراءة فقط:

`/wp-json/mzj-haraj/v1/cars`

إذا كان `MZJ Platform Cars Bridge` مثبتًا، البلجن الجديد يعيد استخدام نفس `X-MZJ-Bridge-Key` تلقائيًا. وإلا ينشئ Secret خاص به ويظهره في:

**WordPress → الإعدادات → MZJ Haraj Bridge**

أضف في Vercel:

```env
MZJ_WORDPRESS_BASE_URL=https://mzjcars.com
MZJ_HARAJ_BRIDGE_KEY=<SECRET>
```

ولا تضع هذا المفتاح في Frontend أو GitHub.

## Firebase

- Firebase Authentication: Admin فقط.
- Firestore: `haraj_accounts` ما زال اسم collection القديم، لكنه في v1.7.0 يمثل **الفروع** للمحافظة على روابط المناديب الحالية.
- `agents`: المناديب وحالتهم وفرعهم.
- `haraj_ads`: التكليفات، Snapshot صيغة الإعلان، رابط حراج وحالة النشر.
- `settings/haraj_publishing`: اسم حساب حراج الواحد + الحد اليومي.

لا توجد Firebase Functions ولا Firebase Hosting.

## PDF

- PDF منفصل لكل فرع ليتم إرساله لمدير الفرع.
- كل إعلانات اليوم تظهر معًا قبل الانتقال لليوم التالي.
- لو يوم واحد يحتاج أكثر من صفحة، يكمل نفس اليوم أولًا.
- سياسات النشر + متابعة الرسائل والتعليقات والقيود تظهر مرة واحدة في **آخر صفحة فقط**.
- لا توجد صفحات فارغة إضافية.
- الـPDF يوضح أن حد حراج هو حد الشركة/الحساب الواحد، وليس حد الفرع.

## سياسات التشغيل المختصرة داخل PDF

- السعر واضح والبيانات والوصف كاملان.
- لا `السعر عند الاتصال` ولا ترويج لحسابات التواصل داخل الإعلان.
- الرد على رسائل حراج داخل المنصة، وليس مجرد إحالة للواتساب/الاتصال.
- متجر حراج واحد فقط في وضع التشغيل الحالي.
- عدم تكرار إعلان نفس السيارة؛ يتم تحديث الإعلان الحالي بدل إنشاء مكرر عند الحاجة.
- متابعة أي قيد أو تنبيه قد يؤثر على حد النشر.
