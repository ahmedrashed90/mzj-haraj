ROOT CAUSE
Vercel TypeScript TS2322 in src/components/OpenSooqSchedule.tsx:
  Type 'Uint8Array<ArrayBufferLike>' is not assignable to type 'BlobPart'.
The XLSX builder's explicit Uint8Array return annotations used the broad
ArrayBufferLike backing type, which includes SharedArrayBuffer and does not
satisfy the stricter BlobPart<ArrayBuffer> constraint.

SOURCE FIX (NO PATCH / NO HOTFIX)
The XLSX generator now declares the actual backing buffer type explicitly:
  concatenate(...): Uint8Array<ArrayBuffer>
  zipXml(...): Uint8Array<ArrayBuffer>
  buildOpenSooqXlsx(...): Uint8Array<ArrayBuffer>
All returned bytes come from `new Uint8Array(total)`, which creates a real
ArrayBuffer-backed typed array. The existing Blob download path is unchanged.
No unsafe casts, extra byte copies, new dependencies, or build bypasses.
